# Workflow: test, delegate, review, release, deploy, merge

Last revised 2026-10-10 (app 0.26.2 released, 0.26.3 in PR #18, backend 0.15.0 deployed). Facts about hosts, ports and knobs live in `environment.md`; mistakes already made live in `gotchas.md`.

## 1. Local backend bench (user space, no root)
- `~/frappe-dev/start.sh` (MariaDB on 3307 root/admin, redis 13000/11000); `source ~/frappe-dev/env.sh`; bench `~/frappe-dev/bench`, site `asoud.test` (erpnext, hrms, asoud_erp); `apps/asoud_erp` is a symlink to `.workers/backend`. After a reboot run `start.sh` first.
- Pure tests: `python3 -m pytest -q asoud_erp/tests` (583). Lint: `uvx ruff check .` (the CI quality job installs only pytest and ruff: guard heavy imports such as Pillow with `pytest.importorskip`).
- Integration: `bench --site asoud.test migrate`, then `bench --site asoud.test run-tests --app asoud_erp --skip-test-records --module asoud_erp.integration_tests.<module>`; all 33 modules: `env PYTHONPATH=<worktree> bash ~/frappe-dev/runall.sh` (every line must say OK).
- Run a worker's code without moving the symlink: `env PYTHONPATH=<worktree> bench ...` (the worktree copy shadows the installed app). Doctype changes still need merge + migrate.
- e2e: `npm --prefix e2e test` in the backend worktree (48 Playwright tests, own server on port 8010).

## 2. Flutter
- SDK `~/frappe-dev/flutter` (keep it off `/tmp`): `export PATH=$HOME/frappe-dev/flutter/bin:$PATH`. `flutter analyze` clean; `flutter test --exclude-tags golden` all green (about 680 tests). Format only files you changed.
- Screenshot review in tests: load Vazirmatn + MaterialIcons with `FontLoader`, set `tester.view.physicalSize`, `matchesGoldenFile` with `--update-goldens`, view the PNGs, delete them.

## 3. Team mode (the manager plans, prompts and reviews; workers code)
- tmux session `erp-team`; helper `<workspace>/.team/bin/team`: `wt app|be NAME BASE` (worktree `.workers/w-NAME`, branch `w/NAME`), `spawn NAME KIND WIN ABS_DIR PROMPT` (**absolute dir**; the prompt file must not already end in `.full.md`: spawn writes `<prompt>.full.md` and a clash truncates it), `say NAME TEXT|@file`, `peek`, `kill`, `list`, `reap`, `qwen-count`, `qwen-usage`, `handoff NAME NEWKIND DIR PROMPT`.
- Kinds in use (2026-10-10): `codexl` = Codex `gpt-5.6-terra` medium (works); `codexs` = `gpt-5.6-sol` medium (was refused by the ChatGPT account on 2026-10-10: always probe with `codex exec -m <model> "Reply OK"` before a big spawn); `flash` = claude-gemini Gemini 3.8 flash medium (often the best finisher; 503/429 come in waves); `qwen`/`qwenx`/`qwenl` = claude-qwen (see `environment.md` for thinking limits; too slow for long agentic loops, fine for short exact edits); `pickle` = OpenCode big-pickle (poor). The user does NOT want Claude Sonnet/Opus as workers; the one exception was the Sonnet UI/UX screenshot reviewer he asked for. Codex warns when under 5% of the monthly limit is left: move to flash.
- **Handoff, never restart**: when a worker hits a limit or dies, `team handoff NAME NEWKIND DIR PROMPT` saves its last screen and starts another model in the SAME worktree with "do not redo finished work; read git log/status/diff first; never reset/stash/checkout".
- Task design (each rule is a defect we hit): at most 3 bugs per task, one commit and one regression test each, "do not stop early", tests built from REAL response shapes, a context pack at the top (`context-pack-template.md`), the exact commands that define "done", and never leave an old instruction next to its replacement (a weak model follows the familiar old one). Do not put secrets in prompt files: send credentials only through `team say @tmpfile` and delete the file.
- Workers never push; the shared pre-push hook refuses pushes from `.workers/w-*`. A worker's `STATUS: PASS` means nothing until section 4 is done. If a report says FAIL or "partial", the work is not finished: send the missing items back.

## 4. Review checklist (every worker, every time)
1. Read the WHOLE report and find ALL its files (a report can sit in the worker's own worktree `.team/reports/`; one full 23 KB live report was almost missed).
2. `git log base..HEAD`, `git diff --stat`, then read the production diff (not only tests). Check for silent fallbacks around permissions, removed assertions (`git diff base...HEAD -- test | grep '^-\s*expect'`; rewrapped lines look like deletions), removed conditions (a dropped `allowOfflinePreview` check nearly shipped a false "saved on phone" message), and anything touching auth, sessions, secrets or the offline queue.
3. Merge into the integration branch (`feat/personnel-v2` in `.workers/flutter`, `feat/backend-v2` in `.workers/backend`), then run `flutter analyze` and the FULL suite yourself (or pytest + `runall.sh` + e2e for the backend). Never pipe `git merge` into `tail` without checking `git log -1`.
4. Undo a bad merge with `git revert -m 1 <merge>`, never `reset --hard`/stash on shared worktrees.
5. Close finished workers (`team kill`), keep the report, remove merged worktrees only when the user agrees (he once said "do not delete anything").

## 4b. Turn every worker's DOUBTS into a review task
A worker's `DOUBTS` line is a bug report from the one who knows the code best: fix-nav wrote «the navigation implementation uses preview dashboard navigation for workflow shell destinations; review it», I merged on green tests, and the live test later showed that tapping «داشبورد» dropped every signed-in user into the offline preview. Read each DOUBT, decide yes/no, and open a task for every one you cannot clear on the spot.

## 5. Live test on emulators (what a "tour" is)
- **Resource limits learned the hard way (2026-10-10/11):** two emulators comfortably, three only with nothing else heavy running. Each read-only emulator writes a temp overlay `/tmp/android-<user>/emulator-*.qcow2` (up to 2 GB) that is NOT removed when the emulator is killed: 21 stale files (10 GB) filled the /tmp quota and even froze the shell (EDQUOT). Before every test run, delete the ones `fuser` says are not open. A lab of 40 Docker containers on the same machine, 4 cores + software GPU per emulator and parallel `flutter test` runs pushed the load average to 182; QEMU then reported a hung thread and died. AVD config now: `hw.cpu.ncore=3`, `hw.ramSize=3G`, `vm.heapSize=512M`, data partition 4G; start emulators one at a time, 60 s apart; never run the full flutter suite while testers are driving emulators.
- Emulator `asoud_phone` (android-36): up to three read-only copies at once: `emulator -avd asoud_phone -read-only -port 5554|5556|5558 -no-snapshot -gpu swiftshader_indirect -no-audio` (each about 3 GB RAM; with 30 GB total keep 3 emulators + 4 workers at most). `.team/bin/emu-up PORT APK USER PWENV` boots, installs and signs in (password read from the named environment variable, never printed).
- Drive the screen only with `.team/bin/ui EMU` (`list`, `tap "TEXT"`, `edit N`, `type`, `back`, `shot NAME`): raw `uiautomator dump` XML is about 50 KB per step and made a qwen worker crawl. `adb input text` types ASCII only; Persian is dropped.
- Test with REAL roles. Demo users `hr-manager|sales-manager|employee|newcomer@asoud-demo.local` share the demo password (it works; a worker once mistyped it and we wrongly concluded it was wrong). `sales-manager` and `newcomer` only have Employee; only Administrator has System Manager, so real accountant/sales/stock roles need server-side role assignment (needs the user's approval).
- Every tester writes a role-access matrix: page | visible | opens | data or 403 | expected | verdict, and a screenshot of every screen into `<workspace>/ui-audit/<date>-v<version>/` with an `INDEX-<id>.md` (UX notes). The folder feeds the UX review (a Sonnet reviewer reads every PNG and writes `ui-audit/UX-REVIEW.md`).
- **Verify before logging a bug**: two phantom bugs (403 for Administrator, accounting lists failing) came from a broken emulator session; a `curl` of the same endpoint as the same user returned 200 with data. Re-test by API (`curl` login + read-only GET) and by a fresh sign-in before accepting a claim.
- Server safety: demo server is live; read-only by default; writes only inside an explicit CREATE rule with `E2E-` names. Never read or print site_config, credentials files or passwords; never put a password in a prompt file or report.
- A signed-in emulator that suddenly shows «نسخه نمایشی آفلاین» lost its session: sign in again before judging anything.

## 6. Releases
- **App**: bump `pubspec.yaml` `X.Y.Z+N` + CHANGELOG, commit `chore(release): X.Y.Z+N`, open the PR; after CI is green and the user merged, take the artifacts of the CI run on `main` (`gh run download <id>`: `asoud-erp-<ver>-debug` and `-release`), tag annotated `vX.Y.Z` on the merge commit, `gh release create --prerelease --target main` with both APKs. Notes (English): changes, paired backend version, analyze/test counts, CI run id, SHA-256 of both APKs, known issues. The release APK is signed with the CI debug key (new key per run): updating over an older build fails with INSTALL_FAILED_UPDATE_INCOMPATIBLE, uninstall first; a fixed keystore in Secrets is still to do.
- **Checklist added after 0.26.0 shipped without INTERNET permission**: before releasing, install the RELEASE apk on an emulator and sign in to the live server with a real user, close the app from recents and reopen it.
- **Backend**: bump `asoud_erp/__init__.py` + `pyproject.toml`, CHANGELOG `## X.Y.Z`, trigger `gh workflow run erpnext-v15-integration.yml --ref <branch>`, tag + pre-release (notes: deploy = `bench --site <site> migrate`, plus the service-user config when System Actions are used).
- Release notes and PR text in English; talk to the user in Persian. No AI mentions anywhere.

## 7. Deploy to the demo server (only with the user's explicit approval; he gave it once for 0.15.0)
Order: backup (`bench backup --with-files`) → build the new image from the running one with the new app dir **and the old image's CMD/ENTRYPOINT restored** (`docker commit --change 'CMD ["start.sh"]'`; verify with `docker inspect`; a `sleep 3600` CMD gave HTTP 502) → copy compose/custom.env to `.before-<ver>` → change the tag → `docker compose -p asoud -f compose.asoud.yaml up -d` → wait for `/api/method/ping` → `bench ... migrate` → service user config if needed → test as Administrator and a non-manager. Keep only the new image and one previous. Never build assets on the 3.8 GB server. Claude Code in Auto mode blocks risky server actions even with allow rules: use Bypass mode (VS Code setting `claudeCode.allowDangerouslySkipPermissions`, then a NEW conversation) or hand the user the commands. Continuous delivery (GitHub Actions + `deploy.sh` with CMD check and rollback) is written locally in `.workers/w-cd-deploy` and deliberately NOT pushed (the user said to wait).

## 8. Merging and PRs
- One PR per repo to `main`; the user merges (self-merge is blocked by the harness). Merge `origin/main` into the integration branch BEFORE opening or updating a PR (main moves: PR #13 and #17 were merged by the user while work continued). New work after a merge goes into a new version and PR (0.26.3 = PR #18).
- `gh pr edit` fails (classic Projects GraphQL error): use `gh api -X PATCH repos/<owner>/<repo>/pulls/<n> -F body=@file`; create PRs with `gh api -X POST .../pulls`.
- Another developer (mohamadi121) also pushes to `main`: fetch and merge before new work; resolve conflicts keeping the stricter permission behaviour.
