# کاتالوگ فارسی مجوزهای آسود

مسیر: **پروفایل‌های دسترسی ← پروفایل جدید / ویرایش پروفایل** یا
**مدیریت کاربران ← جزئیات حساب ← دسترسی‌ها**. هر دو، کاتالوگ را از سرور می‌خوانند.
کاتالوگ فهرست گزینه‌های قابل انتخاب است؛ اضافه شدن ردیف به معنی اعطای مجوز نیست.

| گروه | نمونه ردیف‌های تعریف‌شده در کد |
| --- | --- |
| مالی | سند حسابداری، دریافت و پرداخت، حساب‌ها، هزینه‌های پرسنلی |
| اشخاص و شرکت‌ها | مشتریان، تأمین‌کنندگان، مخاطبان |
| کالا و انبار | کالاها، انبارها، ورود و خروج انبار |
| خرید و فروش | درخواست کالا، سفارش خرید، فاکتور خرید، پیش‌فاکتور، سفارش فروش، فاکتور فروش |
| منابع انسانی | پرونده پرسنلی، واحدهای سازمانی، حضور و غیاب، تردد، مرخصی، مساعده، ارزیابی، فیش حقوقی |
| مکاتبات و امور پرسنلی | نامه‌ها و دستورات، گزارش کار، دعوت‌نامه حساب پرسنل |

این جدول نمونه ردیف‌های کد است، نه فهرست قطعی سرور نصب‌شده. سرور ردیف‌های فاقد نوع سند نصب‌شده، فیلد دفتر یا عملیات پشتیبانی‌شده را حذف می‌کند. وجود «درخواست کالا» در کاتالوگ مجوز نیز به معنی باز شدن ورودی ایجاد درخواست در فهرست درخواست‌های کاربر نیست.

عملیات جدول: **مشاهده، ثبت، ویرایش، حذف**. «ثبت» یعنی ایجاد رکورد، نه تأیید یا ثبت قطعی. مربع خالی یعنی عملیات قابل اعطا است؛ «—» یعنی قابل انتخاب نیست.

## روش توسعه ماژول جدید

۱. کنار کد همان ماژول، نام فارسی ماژول، گروه، عنوان سند، شناسه پایدار نوع سند و عملیات پشتیبانی‌شده را یک‌بار تعریف کنید. تابع همان ماژول این تعریف‌ها را از طریق هوک موجود `asoud_office_permission_catalog` به کاتالوگ بدهد. پس از به‌روزرسانی سرور و بارگذاری مجدد صفحه، ردیف‌های واجد شرایط در هر دو جدول دیده می‌شوند؛ تغییر جداگانه Flutter لازم نیست.

۲. پیش از ارائه هر ردیف، بررسی کنید محدودیت دفتر و عملیات برای فهرست، مشاهده مستقیم، ایجاد، ویرایش و حذف در سرور واقعاً اعمال شوند. اگر API اختصاصی سند از کنترل دیگری استفاده می‌کند، ابتدا همان کنترل را با مجوز واقعی هماهنگ کنید.

۳. اگر چند فرم درخواست روی یک نوع سند مشترک ذخیره می‌شوند، مجوز آن نوع سند **معادل مجوز یک فرم مشخص نیست**. راهکار پیشنهادی این است که انتشار فرم با شناسه پایدار همان فرم، ورودی کاتالوگ را فراهم کند؛ فقط وقتی فهرست، ارسال، مشاهده مستقیم و تغییرات آن فرم همان مجوز را اعمال کنند. پیش‌نویس‌ها به‌طور خودکار گزینه نشوند و نسخه جدید تا وقتی همان فرم است شناسه مجوز را تغییر ندهد. این بخش هنوز خودکار نیست.

۴. برای جزئیات، مثلاً پیوست‌ها یا ردیف‌های درون سند، صرف وجود فیلد کافی نیست. فقط جزئیاتی ارائه شوند که کنترل خواندن و نوشتن، از جمله در API و خروجی‌هایی که آن داده را برمی‌گردانند، جداگانه دارند. در نسخه فعلی، چنین جزئیاتی خودکار عرضه نمی‌شوند.

جزئیات فنی هوک و قرارداد API: [راهنمای اصلی پروفایل‌های دسترسی](access-profiles.md).
