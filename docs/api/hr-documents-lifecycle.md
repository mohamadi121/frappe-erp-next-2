# ماتریس چرخهٔ اسناد منابع انسانی

این جدول برای endpointهای عمومی پنج ماژول `employment_contracts`، `hiring_orders`،
`employment_certificates`، `personnel_introduction_letters` و `salary_change_orders` است؛
ورودی‌ها و envelope هر ماژول در سند API همان ماژول تعریف شده‌اند.

| نقش در شرکت سند | ساخت/ذخیره/ارسال چهار سند اول | ساخت/ذخیره/ارسال تغییر حقوق | دریافت/چاپ چهار سند اول | دریافت/چاپ تغییر حقوق |
| --- | --- | --- | --- | --- |
| HR User | مجاز | ممنوع | مجاز، بدون حقوق | ممنوع |
| HR Manager (طراح) | مجاز | مجاز | مجاز، بدون حقوق | مجاز، بدون حقوق |
| Payroll Manager | ممنوع | ممنوع | ممنوع | مجاز |
| Employee | ممنوع | ممنوع | ممنوع | ممنوع |
| کاربر شرکت دیگر، حتی HR Manager | ممنوع | ممنوع | ممنوع | ممنوع |

HR Manager با مجوز بومی Company و بدون Employee نیز مجاز است.
داشتن نقش طراح یا حقوق، اجازهٔ تأیید وظیفهٔ کاربر دیگری را نمی‌دهد؛ تأیید تنها برای مسئول واقعی وظیفه و با منع تأیید درخواست خود مجاز است.
خطای نقش، شرکت و وظیفهٔ دیگران `PermissionError` با جملهٔ فارسی، بدون نام فیلد یا شناسهٔ داخلی است (HTTP 403).
ارسال با شناسهٔ تکراری نتیجهٔ همان سند را می‌دهد؛ تأیید دوبارهٔ وظیفه بسته‌شده خطای اعتبارسنجی دارد و شماره/نسخه/چاپ را تغییر نمی‌دهد.
نهایی‌سازی از شماره‌گذاری موجود استفاده می‌کند و تکرار رویداد تکمیل شمارهٔ دیگری نمی‌سازد.
`test_hr_documents_lifecycle` این ماتریس را با رکورد واقعی، بدون mock پایگاه داده و بدون تغییر دادهٔ عملیاتی اجرا می‌کند؛ نوشتن فقط در fixture تراکنشی است.
