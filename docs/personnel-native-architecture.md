# اتصال پرسنل به مدل استاندارد

ASOUD افزونهٔ ERPNext/Frappe/HRMS نسخهٔ ۱۵ است. قبل از ایجاد قابلیت، مدل و API استاندارد بررسی می‌شود؛ تنها نیازهای پوشش‌داده‌نشده، بومی‌سازی حسابداری ایران و اطلاعات فنی اتصال در ASOUD قرار می‌گیرند.

| داده | مرجع اصلی |
| --- | --- |
| نام، موبایل، ایمیل، تولد، جنسیت، شروع کار، سمت، واحد، نوع استخدام، آدرس | Employee |
| ورود و خروج | Employee Checkin؛ محاسبهٔ Attendance با قواعد استاندارد شیفت |
| ارزیابی | Appraisal و Appraisal Cycle و الگوی تخصیص‌یافته به کارمند |
| تصویر و مدرک | File خصوصی متصل به Employee |
| یادداشت دستی | Comment متصل به Employee |
| تاریخچهٔ تغییر سند | Version استاندارد، طبق تنظیم track_changes مدل اصلی |
| کد ملی ایرانی، اطلاعات تفصیلی و سایر فیلدهای محلی | افزونهٔ ASOUD |

ستون‌های مشترک قدیمی Party Profile برای سازگاری و جست‌وجو باقی می‌مانند؛ خواندن همیشه مقدار Employee، حتی مقدار خالی، را ترجیح می‌دهد. هوک Employee کش قدیمی را به‌روز می‌کند. نسخهٔ ویرایش شامل تغییرات Employee نیز هست. مبالغ نمایشی موجود در پروفایل جایگزین Salary Structure یا Salary Slip نیستند؛ محاسبات رسمی حقوق باید از Payroll استاندارد استفاده کنند.

`ASOUD Personnel Record` برای داده‌های جدید فقط شناسهٔ سازگار با برنامه، لینک سند اصلی، عنوان/تاریخ نمایشی و توضیح فاقد معادل در Checkin/File را نگه می‌دارد. زمان حضور، امتیاز و محتوای فایل در JSON کپی نمی‌شوند. `ASOUD Personnel Operation` فقط رسید فنی درخواست است و محتوای پرسنلی ندارد. سوابق استاندارد ایجادشده خارج از ASOUD نیز نمایش داده می‌شوند؛ ویرایش آن‌ها از فرم کامل استاندارد انجام می‌شود.

فرم سادهٔ ارزیابی فقط دورهٔ دستی با یک معیار ۱۰۰٪ و بدون معیار خودارزیابی را قبول می‌کند. الگو باید قبلاً در Appraisee دوره به Employee اختصاص یافته باشد. امتیاز ۰ تا ۱۰۰ به امتیاز هدف ۰ تا ۵ تبدیل می‌شود؛ `final_score` توسط HRMS محاسبه می‌شود. دوره و الگوی ساختگی ایجاد نمی‌شود. حضور پردازش‌شده و ارزیابی ثبت نهایی‌شده در فرم ساده قابل ویرایش نیستند.

## نصب و ارتقا

ابتدا از سایت مقصد نسخهٔ پشتیبان تهیه کنید. HRMS را با همان شاخهٔ major نصب کنید:

```sh
bench get-app --branch version-15 hrms https://github.com/frappe/hrms
bench --site SITE install-app hrms
bench --site SITE migrate
```

این تغییر به‌صورت خودکار داده‌های واقعی را منتقل نمی‌کند. سوابق JSON قدیمی تا انتقال موفق قابل مشاهده و فقط‌خواندنی‌اند. ابزار زیر فقط برای اجرای مدیریتی با `bench execute` است و در حالت اعمال، هر ردیف موفق را commit می‌کند؛ از داخل تراکنش دیگری فراخوانی نشود.

```sh
bench --site SITE execute asoud_erp.services.personnel_migration.migrate_legacy_records \
  --kwargs '{"company":"COMPANY","dry_run":true}'
```

`ready_for_validation` یعنی بررسی اولیه موفق بوده؛ اعتبارسنجی کامل کنترلر استاندارد هنگام انتقال اجرا می‌شود. وضعیت `needs_review` باید بررسی شود. کد کارمند از لینک موجود خوانده می‌شود؛ تطبیق اسمی یا ایجاد Employee جدید انجام نمی‌شود. ارزیابی‌های قدیمی نیازمند نگاشت صریح شناسهٔ سابقه به دورهٔ موجود هستند:

```sh
bench --site SITE execute asoud_erp.services.personnel_migration.migrate_legacy_records \
  --kwargs '{"company":"COMPANY","dry_run":false,"evaluation_cycles":{"LEGACY_RECORD":"EXISTING_CYCLE"}}'
```

ردیف‌های موفق در اجرای دوباره منتقل نمی‌شوند. برخورد با ورود/خروج یا ارزیابی موجود برای بررسی انسانی گزارش می‌شود. متن JSON و رسیدهای قبلی حذف نمی‌شوند؛ بعد از انتقال، نمایش از سند استاندارد است. حذف آرشیو به این تغییر تعلق ندارد. خطای انتقال یک ردیف باعث rollback همان تراکنش و حفظ دادهٔ اصلی می‌شود.

## آزمون

```sh
python -m pytest -p no:cacheprovider -q
bench --site TEST_SITE run-tests --app asoud_erp --skip-test-records \
  --module asoud_erp.asoud_erp.doctype.asoud_personnel_record.test_asoud_personnel_record
```

سایت تست باید Frappe، ERPNext، HRMS و ASOUD نصب‌شده داشته باشد. آزمون‌های اتصال از مدل‌های واقعی استفاده می‌کنند و ثبت تکراری، نسخهٔ قدیمی، فایل خصوصی، ارزیابی و انتقال داده را بررسی می‌کنند.
